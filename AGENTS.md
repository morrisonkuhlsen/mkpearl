# Pearl — instructions for agents

Pearl is an open-source, Rust-native document editor for Typst: source on the left, live pages on the right, a ribbon on top, real-time sessions, version history and Claude as a person in the session. It runs natively on Linux, Windows and macOS. A Morrison Kühlsen project. Siblings with the same conventions: `../mkperth`, `../mksigma` and `../matrix`, whose interface Pearl follows.

## Start every session here
1. Read [`docs/roadmap.md`](docs/roadmap.md): what is done, and the **Next:** items, which are the work list; then the relevant section of [`docs/architecture.md`](docs/architecture.md).
2. Work autonomously through the next item: build it, test it, look at it, commit it when the gates pass. Stop to ask only for what is the user's to decide: priorities and scope, brand and visual identity, anything published or shared (pushing, releases), and anything destructive.
3. **Issues.** The open GitHub issues (`gh issue list`) are work too. A problem found and not fixed in the same change becomes an issue at once (`gh issue create`), in English, following the templates in `.github/ISSUE_TEMPLATE/`: `[Bug Report] …` with *Summary*, *Steps to reproduce*, *Expected* and *Actual behavior*; `[Feature Request] …` with *Description*, *Proposal* and *Acceptance*; `[Decision] …` for what is the user's to decide; labelled by type (`bug`, `enhancement`, `decision`) and priority (`priority: critical`, `high`, `medium`, `low`; `needs info` when it can't be confirmed). Search the open issues first. A commit that fixes one says `Fixes #n`.

`plan/` is gitignored (local only): working notes.

## Assets — absolute rule
**No other vendor's or project's iconography, images, artwork, fonts, templates or themes without a licence for redistribution — ever.**
- Every asset is original work by Pearl's contributors, or public domain / CC0, or licensed for redistribution, or one of Morrison Kühlsen's brand assets.
- Every asset file has a row in [`ATTRIBUTION.md`](ATTRIBUTION.md). `cargo xtask assets` enforces it.
- Prefer art generated in code. The theme, widgets and icons come from MK Matrix, under its licence, as `NOTICE` says.
- The Morrison Kühlsen brand files in `docs/brand/` are the one exception to redistribution, under `docs/brand/LICENSE.md`.
- **Typst's name and logo:** the name may refer to the compiler, as "Typst 0.15" does; the logo is not used. Nothing may imply that Pearl is Typst or is endorsed by it. Any commercial use needs Typst's authorization first (https://typst.app/legal/brand/).

## Never crash
People trust Pearl with their writing; a crash loses their work. **This outranks feature work.**
- **No panics in non-test code:** no `unwrap()`, `expect()`, `panic!`, `unreachable!`, `todo!`, `unimplemented!`; no `unsafe` (`forbid(unsafe_code)`). `cargo xtask panics` enforces the attributes.
- **Input is hostile:** documents, project files, session messages, the API's replies and recovery files. Use `get()` instead of indexing, checked arithmetic and caps on input-sized allocations. The compiler runs inside `catch_unwind`, so a Typst panic never takes the text with it.
- **Text survives.** What the user wrote is never overwritten without a version in the history, and unsaved text has a recovery copy. A failure to write says so.
- **Prove it:** every crash fix lands with a regression test that feeds the input that crashed.

## Non-negotiables
- **Dependencies** are permissively licensed (MIT, Apache-2.0, BSD, Zlib or similar). Exceptions are the user's to accept and are listed here:
  - `option-ext` (MPL-2.0), through Typst.
  - `spellbook` (MPL-2.0) and the VERO dictionary (LGPLv3 and MPL), for spell checking; accepted November 2026 (#6). They stay unmodified; a change to them is published under their terms.
- **GPL.** Typst embeds the font NewCM10-Regular (GPL-3 or later with a Distribution Exception). The exception holds only while the font is unmodified and Pearl's licence stays compatible with GPL-3: Pearl can't become closed source while it ships that font. Never copy GPL, AGPL or LGPL code.
- **Licences travel with the program.** `THIRD-PARTY-LICENSES.txt` is generated by `cargo run --example licenses` and shown in the app; a test fails when it falls behind `Cargo.lock`.
- **Languages.** Every user-visible text comes from the catalogs in `locales/*.ftl` through `tr!`, in English and Português (Brasil); their tests fail on a missing message or placeholder.
- **Secrets stay.** The API key is stored only locally, readable by this user alone, and never reaches a session's peers. Claude never spends the user's credits without their approval: tests use a pretend server.
- **Sessions** are encrypted end to end with the key in the link; a peer's message is hostile input.
- **Not a target yet:** WebAssembly, and the layering of the siblings. Pearl stays one crate until something needs the split (decided in #1).
- **CHANGELOG.** Anything a user would notice gets a line in [`CHANGELOG.md`](CHANGELOG.md) under `## [Unreleased]`.
- **Quality gates** before every commit: `cargo xtask ci` (fmt, clippy -D warnings, tests, assets, panics). Run it as `cargo xtask ci && git commit …`: a pipe after it hides its failure. One change per commit, its message saying what and why. Push only when the user asks.
- **Look at it.** Render the window offscreen with `cargo run --example shot -- out.png [tab] [dark]`; never capture the user's screen.
